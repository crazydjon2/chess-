# Инструменты проверки Chess+

Два инструмента:

- **баланс-лаборатория** (`tools/balance`): тысячи партий ИИ против ИИ, отчёт о том, где перекос;
- **UI-тестер** (`tools/ui-e2e`): прокликивает игру в настоящем браузере и ищет, где ломается интерфейс.

Отчёты складываются в `reports/` внутри каждого инструмента (в git не попадают). Последний отчёт баланса всегда лежит в `tools/balance/reports/latest.html`.

## Баланс-лаборатория

```bash
npm run balance:quick       # ~1 мин, слабый ИИ — проверить, что ничего не сломалось
npm run balance             # ~15 мин, обычный ИИ — основной прогон
npm run balance:deep        # час+, сильный ИИ и много партий — перед важным решением
node tools/balance/run.js cards items --n 30   # только нужные эксперименты
```

### Эксперименты

| Эксперимент | Что показывает |
|---|---|
| `mirror` | одинаковые армии: преимущество первого хода, поведение каждой доски |
| `items` | случайные армии: сколько побед приносит каждая фигура и карта относительно своей цены, «честная цена» |
| `archetypes` | стратегии драфта друг против друга: есть ли доминирующая или бесполезная |
| `meta` | вся мета: фигурные планы × карты + человекоподобные драфтеры, каждый с каждым (долго: n=2 ≈ 40 мин); в отчёте — отклонение от 50% и самые перекошенные пары |
| `cards` | каждая карта против той же армии без неё |
| `placement` | стили расстановки и выгода того, кто правит её последним |
| `skill` | сильный ИИ против слабого: насколько исход решает умение, а не случай |
| `fuzz` | хаотичная игра и фаззинг сервера: падения, нарушения правил, утечки скрытой информации |

### Как читать отчёт

- **«Где перекос»** — всё найденное, отсортированное по важности. Пороги лежат в `LIMITS` в `lib/analysis.js`.
- **Надёжность.** В таблицах есть доверительные интервалы и z. Результат с |z| < 2 — шум.
- **Ограничения ИИ.** ИИ — поиск на 1–3 хода вперёд с оценкой позиции. Он хорошо видит тактику и плохо — дальние планы. Поэтому **сравнения** («карта А сильнее карты Б», «стратегия X доминирует») надёжнее **абсолютных** чисел (например, доли ничьих: ИИ хуже человека дожимает эндшпили).

### Сравнение «до/после» правки правил

```bash
npm run balance -- --save-baseline   # запомнить текущее состояние
# ...меняешь правила...
npm run balance -- --compare         # отчёт покажет, какие метрики сдвинулись
```

### Воспроизвести конкретную партию

У каждой партии свой сид. Чтобы увидеть армии, расстановку и все ходы:

```bash
node tools/balance/run.js --replay tools/balance/reports/<дата>/results.json <номер партии>
```

### Когда меняются правила

- **Новая карта, фигура или доска** подхватываются автоматически: каталог, цены, доски и ход игры берутся из кода самой игры. ИИ пробует карту через настоящий движок и сам решает, когда она выгодна.
- **Карта с совершенно новым видом состояния** (не фигуры, HP, заморозка, нестабильность, метеоры, мины, туман) требует добавить строку оценки в `lib/ai/eval.js` — место помечено комментарием `HOOK`. Иначе ИИ не поймёт её ценность и будет недооценивать.
- **Новая фигура в драфте**: можно добавить архетип в `lib/ai/draftAI.js` (`ARCHETYPES`).
- **Новое правило**, которое должно выполняться всегда: проверка в `lib/invariants.js`. Она прогоняется после каждого действия в каждой партии.

## UI-тестер

Нужен установленный Chrome или Edge.

```bash
npm run ui-test              # десктоп + телефон, все сценарии (~5 мин)
npm run ui-test:all          # + ноутбук, маленький телефон, планшет
node tools/ui-e2e/run.js --headed --only online   # смотреть глазами один сценарий
```

Сценарии: тур по меню (все окна, песочница с ходами и картами, журнал), полный онлайн-матч двумя браузерами (лобби, драфт, расстановка, бой, карты, ничья, перезагрузка посреди боя, «Назад», сдача, итоги, следующие раунды), ссылка-приглашение и «обезьяна» (случайные клики).

На каждом экране проверяются: ошибки JS и консоли, пустой экран, горизонтальная прокрутка, прокрутка там, где её быть не должно (бой и расстановка на телефоне), кнопки за краем экрана или перекрытые другими элементами, слишком мелкие кнопки для пальца. Каждый шаг сохраняет скриншот, при падении снимаются экраны обоих игроков и сообщение, которое игра им показала.

Тестер кликает по доске через тестовые атрибуты: `data-testid="board"` с `data-mode`/`data-targets`/`data-card-targets` и `data-square`/`data-piece` на клетках. Если менять вёрстку доски, эти атрибуты нужно сохранить.
